## Resilience and recovery

External-internet resilience means local servers and the browser can still communicate. DevTools' global Offline mode may also block the local API, so use it only for testing the app's error/retry state. Source websites will require internet even when the local evidence view works.

If a provider is unavailable, show the labelled snapshot or prepared response and its date. If a local request fails, show the visible retry path. If a source is missing, show the missing state. If the on-stage environment prevents the full journey, use the prepared second tab, say it contains a saved plan, and continue through its evidence. Do not substitute invented live results.

## Answers for judges

- **What decision does it make easier?** Choosing the first career route to explore and a practical next action, while preserving alternatives.
- **What is the AI doing?** Preliminary offline embedding affinities support interest matching. Ranking is deterministic. The visible guide uses prepared information and citations; no live model is required.
- **How broad is it?** The launch evidence catalogue covers 412 occupation profiles. Interest matching is limited to 20 roles; training-route and history coverage vary.
- **What has been validated?** State only the final verification results recorded by the release owner. Synthetic development results and historical tier backtests do not establish real-learner matching accuracy.
- **What could become a business?** Free learner entry, followed by a school/adviser pilot testing whether evidence review and plan follow-through improve. Proposed pricing and adviser features remain hypotheses; see the [business case](business-case.md).
